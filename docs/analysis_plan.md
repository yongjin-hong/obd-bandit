# 분석 계획: Open Bandit Dataset 기반 밴딧 알고리즘 시뮬레이션

## 1. 데이터

### 무엇인가
- **Open Bandit Dataset (OBD)**: 일본 패션 이커머스 ZOZOTOWN의 추천 영역에서 수집된 실제 로그
- 두 추천 정책(**Random**, **Bernoulli Thompson Sampling(BTS)**)을 A/B 테스트로 동시에 운영하며, 사용자에게 무엇을 보여줬고 클릭했는지 기록
- 2019년 11월 말, 7일간 실험으로 수집
- 출처: [research.zozo.com/data.html](https://research.zozo.com/data.html) (전체 버전), `obp` 패키지 내장 (소용량 버전)

### 구성
| 구분 | 내용 |
|---|---|
| 파일 단위 | 로깅 정책(random, bts) × 캠페인(all, men, women) |
| 1행 | 노출 1건 |
| 행동 | 노출한 아이템, 추천 위치(3개 슬롯 중 하나) |
| 결과 | 클릭 여부 |
| 컨텍스트 | 사용자 피처, 사용자-아이템 친밀도 |
| 정책 정보 | propensity score (해당 아이템이 선택될 확률) |
| 별도 파일 | 아이템 피처 |

> 정확한 컬럼 구성은 EDA에서 확인

## 2. 어떤 분석을 하는가

random 로그를 시간순으로 재생(**replay**)하며, 여러 밴딧 알고리즘이 **실시간으로 학습하는 과정을 시뮬레이션**한다.

| 구분 | 정책 |
|---|---|
| 기준선 (실제 로그) | Random, BTS |
| 비컨텍스추얼 (시뮬레이션) | ε-greedy, Bernoulli TS |
| 컨텍스추얼 (시뮬레이션) | LinEpsilonGreedy, LinUCB, LinTS |

## 3. 왜 하는가

### 상황 설정
추천팀은 현재 BTS를 운영 중이다. 사용자 정보를 활용하는 컨텍스추얼 밴딧으로 교체하면 효과가 있을지 궁금하지만, 새 알고리즘마다 A/B 테스트를 돌리는 것은 비용과 리스크가 크다.

### 목적
- 실제 배포 없이 로그만으로 **알고리즘 교체 가치를 사전에 판단**
- 사용자 피처 활용(컨텍스추얼)이 실제로 효과가 있는지 확인

### 분석 질문
- 컨텍스추얼 밴딧이 BTS보다 클릭률이 높은가?
- 사용자 피처를 쓰는 것이 쓰지 않는 것보다 효과가 있는가?
- 학습은 얼마나 빨리 수렴하는가?

## 4. 결과물

| 결과물 | 내용 |
|---|---|
| 정책별 클릭률 비교표 | Random, BTS, 시뮬레이션 정책들의 클릭률 |
| 누적 클릭률 추이 그래프 | 정책별 학습 속도와 수렴 양상 |
| 결론 | 교체 권장 정책, 근거, 한계 |
| 분석 노트북 | 전체 과정의 코드와 해석 |

## 참고: 진행 범위와 단계

### 범위
- 캠페인: **men**으로 시작 → **all**로 확장
- 데이터: **소용량 버전**으로 개발 → **전체 버전**으로 최종 실행

### 단계
| 단계 | 내용 |
|---|---|
| 0. 환경 구성 | uv 프로젝트, Python 3.9.13, obp·polars 설치 |
| 1. EDA | 컬럼 구조, 클릭률 분포, 아이템·위치 분포, 사용자 피처 |
| 2. 시뮬레이션 | 정책별 replay 실행, 하이퍼파라미터 조정 |
| 3. 비교 및 결론 | 지표 비교, 시각화, 정책 교체 판단 |
| 4. 확장 | all 캠페인으로 재실행 |

### 평가 지표
- **replay 클릭률**: 알고리즘 선택과 로그가 일치한 라운드의 평균 클릭률
- **누적 클릭률 추이**: 학습 속도
- **일치 라운드 수**: 추정값의 신뢰도
- **시드 반복 실행**: 결과의 분산

### 리스크와 한계
- **낮은 일치율**: replay는 선택이 로그와 일치할 때만 학습하므로, 최종 결과는 전체 버전 기준으로 판단
- **추천 위치(3개 슬롯) 처리 방식**: EDA 후 결정
- **정상성 가정**: 기간 중 사용자 행동이 변하지 않는다고 가정
- **obp 호환성**: 마지막 릴리스가 2023년이라 Python 3.9 환경 사용
