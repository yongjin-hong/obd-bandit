# 분석 계획: Open Bandit Dataset 기반 밴딧 알고리즘 시뮬레이션

> 최종 수정: 2026-11-02 (EDA 완료, 시뮬레이션 설계 전)

## 1. 데이터

### 무엇인가
- **Open Bandit Dataset (OBD)**: 일본 패션 이커머스 ZOZOTOWN의 추천 영역에서 수집된 실제 로그
- 두 추천 정책(**Random**, **Bernoulli Thompson Sampling(BTS)**)을 A/B 테스트로 동시에 운영하며, 사용자에게 무엇을 보여줬고 클릭했는지 기록
- 2019-11-24 ~ 2019-11-30, 7일간 수집
- 출처: [research.zozo.com/data.html](https://research.zozo.com/data.html) (전체 버전), `obp` 패키지 내장 (소용량 버전)

### 구성
| 구분 | 내용 |
|---|---|
| 파일 단위 | 로깅 정책(random, bts) × 캠페인(all, men, women) |
| 1행 | 노출 1건 |
| 행동 | `item_id` (men 기준 0~33, 34개), `position` (슬롯 1~3) |
| 결과 | `click` (0/1) |
| 컨텍스트 | `user_feature_0~3` (해시된 범주형 4개), `user-item_affinity_*` (아이템 수만큼) |
| 정책 정보 | `propensity_score` (random은 전 행 1/34) |
| 별도 파일 | `item_context.csv`: `item_feature_0` (수치형), `item_feature_1~3` (해시된 범주형) |

### 사용 데이터 (men 캠페인, 전체 버전)
| 로그 | 원본 행 수 | 중복 제거 후 | 클릭률 (중복 제거 후) |
|---|---|---|---|
| random | 452,949 | 452,868 | **0.4946%** |
| BTS | 4,077,727 | 4,076,779 | **0.6528%** (Random 대비 1.32배) |

### 데이터 정리 규칙
- 이름 없는 인덱스 컬럼 삭제, `timestamp`를 datetime(UTC)으로 변환
- **중복 행 제거**: 동일 시각·아이템·슬롯·클릭이 반복 기록된 행(전부 클릭=1, 클릭 로그 중복으로 추정)을 1행만 남김. random·BTS 모두 적용
- **아이템 피처는 전체 버전 파일 사용**: 소용량 버전과 범주형 해시값이 다름 (수치형은 동일)

## 2. 어떤 분석을 하는가

random 로그를 시간순으로 재생(**replay**)하며, 여러 밴딧 알고리즘이 **실시간으로 학습하는 과정을 시뮬레이션**한다.

- **replay 원리**: 알고리즘이 고른 아이템이 로그의 아이템과 일치할 때만 결과를 기록하고 학습. random 로그는 모든 아이템이 1/34 확률로 노출되었으므로, 일치한 행들은 편향 없는 표본이 됨
- **BTS 로그는 replay에 쓰지 않음**: 아이템 선택이 균등하지 않아 편향이 생김. 실제 운영 성과(기준선)로만 사용

| 구분 | 정책 |
|---|---|
| 기준선 (실제 로그) | Random, BTS |
| 비컨텍스추얼 (시뮬레이션) | ε-greedy, Bernoulli TS |
| 컨텍스추얼 (시뮬레이션) | LinEpsilonGreedy, LinUCB, LinTS |
| 추가 검토 | 세그먼트별 MAB (특수 그룹 / 나머지로 나눠 각각 비컨텍스추얼 밴딧 운영) |

### 구현 방식
- `obp`는 **소용량 데이터 제공 용도로만** 사용
- 피처 전처리, replay 시뮬레이터, 밴딧 정책은 **numpy·polars로 직접 구현**

## 3. 왜 하는가

### 상황 설정
추천팀은 현재 BTS를 운영 중이다. 사용자 정보를 활용하는 컨텍스추얼 밴딧으로 교체하면 효과가 있을지 궁금하지만, 새 알고리즘마다 A/B 테스트를 돌리는 것은 비용과 리스크가 크다.

### 목적
- 실제 배포 없이 로그만으로 **알고리즘 교체 가치를 사전에 판단**
- 사용자 피처 활용(컨텍스추얼)이 실제로 효과가 있는지 확인

### 분석 질문
- 컨텍스추얼 밴딧이 BTS(0.6528%)보다 클릭률이 높은가?
- 사용자 피처를 쓰는 것이 쓰지 않는 것보다 효과가 있는가?
- 단순한 세그먼트 분리만으로 컨텍스추얼 밴딧만큼의 효과를 낼 수 있는가?
- 학습은 얼마나 빨리 수렴하는가?

## EDA 결과 요약 (men, random, 전체 버전)

### 슬롯
- 클릭률 1번 0.525% > 2번 0.503% > 3번 0.456%
- 1번과 3번의 신뢰구간이 거의 겹치지 않는 수준. 위치 효과는 있을 수 있으나 작음

### 아이템
- 아이템별 클릭률 0.32% ~ 0.75% (최대 약 2.4배)
- 상위와 하위의 신뢰구간이 겹치지 않음 → **아이템 간 차이는 실제로 존재**
- 상위 아이템(13, 31, 3번 등)은 BTS 기준선보다 높지만, 신뢰구간이 기준선을 포함

### 사용자 피처
- 범주 수: `user_feature_0~3` = 4 / 6 / 11 / 10개. 분포가 크게 치우쳐 있고 희귀 범주(비중 1% 미만) 존재
- **특수 그룹**: `uf0_1 = uf1_1 = uf2_0 = uf3_0`인 동일 사용자 집단 (노출의 29%). 의미는 해시 처리로 알 수 없음
- 특수 그룹 클릭률 0.640% vs 나머지 약 0.45%로 확실히 높음
- 사용자-아이템 친밀도는 0이 아닌 값이 0.17%로 매우 희소

### 컨텍스추얼 밴딧의 근거
- 메인 그룹(`uf0_0`, 61%)과 특수 그룹(29%)의 아이템 선호 순위 상관이 0.36으로, 노이즈만으로 기대되는 최대치(약 0.67)보다 크게 낮음
- 상위 5개 아이템 중 겹치는 것은 1개뿐 → **두 그룹의 취향이 실제로 다름**
- 그 외 작은 그룹들은 데이터 부족으로 선호 차이를 판단할 수 없음

### 평가 지표
- **replay 클릭률**: 알고리즘 선택과 로그가 일치한 라운드의 평균 클릭률
- **누적 클릭률 추이**: 학습 속도
- **일치 라운드 수**: 추정값의 신뢰도
- **시드 반복 실행**: 결과의 분산

### 피처 설계 방향 (설계 단계에서 확정)
- 사용자 피처는 원-핫 인코딩, 인코딩 기준은 전체 버전 데이터
- 희귀 범주는 "기타"로 묶는 것을 검토 (과적합 방지)
- 사용자-아이템 친밀도는 우선 제외, 추가 실험으로 검토

### 리스크와 한계
- **클릭 부족**: replay 일치 라운드 약 1.3만 건, 예상 클릭 약 65건. 학습과 정책 간 비교 모두 빠듯함 → 설계 단계 첫 논의 주제
- **추천 위치(3개 슬롯) 처리 방식**: 설계 단계에서 결정
- **정상성 가정**: 기간 중 사용자 행동이 변하지 않는다고 가정
- **해석 한계**: 피처가 해시 처리되어 있어 그룹의 실제 의미는 알 수 없음
